# Data Guide — OPCAL‑MLT

This guide documents the expected folder structure for raw and derived data so collaborators can reproduce experiments.

## Recommended hierarchy
```
data/
  raw/              # Source recordings exactly as received (immutable)
  interim/          # Optional intermediate artifacts
  processed/        # Final datasets ready for analysis or publication
  labeled_sessions/ # Exported Streamlit sessions (labels.csv, peaks.csv, etc.)
  docs/             # Additional metadata such as logs or experiment notes
```

- `data/raw/` — store original inputs for provenance; never overwrite.
- `data/labeled_sessions/` — copy every session directory produced by the app here for backup.
- `data/processed/` — use for merged label datasets or feature tables.

## Standard session files
| Path | Description | Generated by |
| --- | --- | --- |
| `<recording>/<timestamp>_<annotator>/session.csv` | Session header metadata | `SessionService.start` |
| `<recording>/<timestamp>_<annotator>/labels.csv` | Annotated cells + processing metadata | `LabelingService.save_label` |
| `<recording>/<timestamp>_<annotator>/peaks.csv` | Peak information per label | `LabelingService.save_label` |
| `<recording>/<timestamp>_<annotator>/cell_map.csv` | Mapping from cell index to cell ID | `session_io.write_cell_map` |
| `<recording>/<timestamp>_<annotator>/session.log` | Text log of actions | `SessionLogger` (optional) |

## Backup strategy
- Plan to run `scripts/backup_sessions.py` (to be implemented) to archive `data/labeled_sessions/` into a dated ZIP each day.
- Keep at least one off-machine copy (network share, cloud storage) for long-term preservation.

## Sample data
- Unit tests rely on fixtures under `tests/data/`. Do not mix them with real recordings.
- Consider maintaining a private, Git-ignored `data/README.private.md` if storing sensitive datasets.
